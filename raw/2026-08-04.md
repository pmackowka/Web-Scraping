Why is graph engineering suddenly everywhere, weren't we just talking about loops?

Here are the 6 terms you need to know to keep up:

(Plot twist: a loop is just one node inside the graph.)

Graphs are hot right now for one reason, loops alone got flaky. An agent that just acts → checks → repeats is powerful, but you can't reason about where it'll go. A graph gives you the map: fixed states, clear routes, and checks you control.

𝟭. 𝗡𝗼𝗱𝗲
One step in the graph. It can hold a single tool call, an agent, or a whole loop that works something out before handing the result off. The unit of work.

𝟮. 𝗘𝗱𝗴𝗲 / 𝗥𝗼𝘂𝘁𝗲
The paths you draw between nodes. One node can have several outgoing routes, the work only travels one of them.

𝟯. 𝗖𝗼𝗻𝗱𝗶𝘁𝗶𝗼𝗻𝗮𝗹 𝗘𝗱𝗴𝗲
The decision point. It reads the current state (with code logic or an LLM) and picks where the work goes next. This is where your quality gates and safety checks live.

𝟰. 𝗦𝘁𝗮𝘁𝗲 𝗠𝗮𝗰𝗵𝗶𝗻𝗲
The shape of the whole thing. Every node is a state the work can be in, and a check at each one decides the next hop. Built a flow in n8n? You already drew one.

𝟱. 𝗦𝗵𝗮𝗿𝗲𝗱 𝗦𝘁𝗮𝘁𝗲
One object that travels the entire graph; every node reads it, updates it, hands it on. The state machine is the 𝘴𝘩𝘢𝘱𝘦; shared state is what actually moves through it. { messages, context, next }

𝟲. 𝗔𝗴𝗲𝗻𝘁 𝗟𝗼𝗼𝗽𝘀
The autonomous part. The agent acts, evaluates the result, and repeats, no human poking it at every step. It runs until the task is done.

So loops didn't die. They moved 𝘪𝘯𝘴𝘪𝘥𝘦 the graph.

Loops give your agent freedom.
Graphs give you control.

The good systems in 2026 use both, a loop where you want autonomy, a graph around it for everything you can't afford to get wrong.

Loops or graphs, which are you reaching for more right now? 🤔
